# 240 条指令评测方法

`local_stack_240.json` 在评测前固定，包含 240 条不同中文指令。提示词未根据本轮结果修改；这是一组人工构造的功能/边界用例，不是来自独立用户群的随机语料，也不是总体准确率的统计抽样。

## 分层口径

1. **本地模型理解**：所有 240 条强制调用 Qwen3-4B，包括精确规则可处理的指令。每次只有系统规则与当前文本，不带上轮上下文。JSON 解析失败、字段/参数不符均算失败。
2. **产品规则 + 本地 + 模拟图**：复用同一轮模型输出，加入实际精确规则和硬件校验；动作参数和任务结果都正确才算通过。导航请求需要正确识别并被底轮策略拒绝。澄清类样本需返回有效的聊天/澄清，并且没有设备动作。
3. **合成语音**：每条文本经本地 Matcha 合成，PCM 直接送入 SenseVoice，再调用本地模型。属于数字音频测试，不经过喇叭/麦克风；ASR 精确匹配忽略标点空白，不把谐音看作匹配。
4. **端云协同**：复用第 1 层的本地输出，再进入与服务相同的 HybridIntentModel。解析、结构、参数或本轮指令核对失败时转云端，云端输出再校验。测试最多 30 次回退尝试，固定随机种子 20260907 决定顺序；达到上限后返回澄清。结果包含预算约束，不代表无限云端额度时的成绩。
5. **48 条实机语音**：预选头部、前后摄像头、查询、否定句、导航限制、会议和任务控制。通过真实喇叭播放本地 TTS，用实际麦克风录入，经过 ASR、规则/端云模型和图执行。没有投食或米家调用，底轮禁止。设备执行要获得反馈确认。这是受控回放声学测试，不是 48 位真人说话测试。

## 解释结果

- 模型理解率、完整任务成功率、已派发设备动作完成率是不同指标；不得把工程单元测试或设备接口全部成功称为模型 95%。
- 云端无效建议被拦截后，如果原请求就是应当澄清的请求，可以算产品正确处理；不能算云端模型答对。
- 模拟阶段会评测灯、投食和运动计数的图行为，但不据此声称这些设备或视觉能力已经实机通过。
- 实机结束请求失败时，测试框架的最终清理单独记录，不能把框架清理当成用户语音结束指令成功。
- 首次评测发现“你能开灯吗”能力询问校验遗漏，随后补了一个词形拦截及单元测试。原始 240 条报告保留修复前成绩，不回填该用例为通过。

复现命令（机器人新项目目录；实机脚本运行前需停 App 以释放硬件所有者锁）：

```bash
PYTHONPATH=src .venv/bin/python scripts/local_stack_benchmark.py --output unique_new_run
PYTHONPATH=src .venv/bin/python scripts/hybrid_benchmark.py
PYTHONPATH=src .venv/bin/python scripts/hardware_voice_benchmark.py
```

后两脚本固定读取/写入首轮目录，若需新一轮应明确更改路径，防止无意覆盖本轮原始结果。云端预算不因脚本重启清零。
