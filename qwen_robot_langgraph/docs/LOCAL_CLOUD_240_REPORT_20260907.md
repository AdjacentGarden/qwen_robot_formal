# 本地 Qwen3-4B 与端云协同：240 条指令评测报告

日期：2026-09-07。机器人：100.77.107.76。独立项目：`/home/test/qwen_robot_langgraph`。

**已接入端云协同，保留云端 Qwen，本地 Qwen3-4B 优先；ASR/TTS 默认使用本地资源。当前评测尚未达到 95%。**

## 当前运行方式

语音输入 → 本地 SenseVoice → 精确指令规则 → 本地 Qwen3-4B → 必要时云端 Qwen → 指令/参数/硬件限制校验 → LangGraph 任务 → 本地 Matcha 播报。

本地 JSON 解析失败、结构/参数不符合约定，或与当前请求的核对失败时，会请求云端。云端输出仍需要校验。任一模型都不能直接执行设备操作。格式有效但语义错误的提议仍可能漏过；当前没有可靠的通用模型置信度估计，也不是多轮对话理解已完备的版本。

服务以 `python3 scripts/app_service.py start hybrid` 运行，默认也是 hybrid。保留 `start local` 与 `start cloud`，便于独立排查。模型服务器运行在 `127.0.0.1:18087`，控制台在机器人 `127.0.0.1:18884`，电脑现有转发地址为 `http://127.0.0.1:28884`。

**当前云端回退受本轮测试预算保护暂停。** 自充值后累计发起 49 轮生成请求（48 次意图、1 次语音）；另有 51 次连接尝试，保守台账合计 100/100。没有清零或绕过额度。云端代码和配置保留，本地模型、ASR/TTS 与精确规则继续运行。此处生成请求数不是“成功回答数”，解析失败等也记入请求。

## 测试规模和评分

固定 **240 条不同指令**，在测试开始前确定。每条分别走文本、本地 TTS→ASR 合成语音链路；同批文本还评估端云回退。另从这些用例预选 **48 条**做真实喇叭/麦克风及硬件测试，并额外检查服务录音 API。不能将它们说成 528 条不同指令或 240 条全部实机动作。

测试覆盖头部 36 条、前后摄像头 32 条、时间/状态 32 条、灯 20 条、投食 20 条、会议 24 条、运动 12 条、任务控制 12 条、否定/假设/能力询问 32 条、模糊/多动作/未支持指令 20 条。

评分按固定 JSON 意图结构及参数核对。需要澄清的请求必须返回有效澄清而且不执行设备动作；导航请求必须理解正确并被底轮限制拦截。完整任务评分还要求执行图得到预期结果。对“你能开灯吗”等表达，本项目的预设是能力询问应澄清；这种产品约定也会影响分数。

## 端云结果的预算影响

端云文本评测复用同一批本地真实输出，按固定随机种子 20260907 排序，未额外重复本地推理。路由为：精确规则 21、本地校验通过 106、云端输出校验通过 21、最终澄清 92。

实际云端回退尝试 30 次；其中 27 个用例最终处理正确，但其中包含“云端建议仍错误、系统正确澄清”，不能说云端模型准确率为 90%。另有 83 条达到本次 30 次回退上限后没有调用云端，其中 55 条原本是可执行请求，因此低预算显著限制了任务完成率。178/240 既不是不限额端云成绩，也不全是云端提升。

按需求拆开看：188 条动作/工作流/控制请求中正确处理 128 条（68.1%，包含正确阻止导航）；52 条应澄清请求中正确处理 50 条（96.2%）。不得将后者当成整体 95%。

## 实机具体结果

- 抬头：3/3；回正语音：1/3。另两条“归中”相关请求分别被识别为“求故归踪”“请你把头发规住”，没有派发回正，不是头部电机执行失败。
- 前摄：4/6；后摄：5/6。短语“前摄拍照”“后摄拍照”出现“点开纱照”“后续拍照”等识别错误；较完整的“用前面的摄像头……”表达表现更好。
- 时间：6/8；状态：6/8。云端成功修正过本地结构错误；失败中有语音失真、云端超时和预算不足。
- 原地会议启动：1/1；暂停：1/1；继续：0/1；结束：1/1。“请继续当前任务”被识别为“请继续跟写任务”，随后回退受预算拦截。
- 导航请求正确识别并拒绝：3/4；第 4 条也没有导航，但理解未成功，仍记失败。底轮命令实际发送数始终 **0**。
- 6 条否定请求均正确不执行。
- 48 条中共有 11 条失败，4 条的最终阻断原因涉及累计云端预算耗尽；这些请求中部分同时存在 ASR/本地模型错误，原因不能简单互斥相加。

会议结束指令完成后，投影关闭、头部回正、雷达恢复。音量保持 40%。米家凭证没有处理，也没有投食或调用米家控制。

## 目前的主要问题

1. **本地模型结构输出不稳定。** 文本测试 59 条发生解析/调用错误。常见例子是把 `system.time` 放到 `type`，漏掉 JSON 引号，或把投食数量写成未加引号的中文/全角数字。本地时间、状态、投食及运动参数类在这套严格契约中成绩很低。
2. **语音链路会丢字或出现同音替换。** 合成音频直接送 ASR 已存在问题，真实播放回采进一步受 TTS 发音、声学环境、录音和 ASR 共同影响。不能只凭这轮测试断言是单一 ASR 模块故障，也不能代表真人语音效果。
3. **校验规则还有误拦截。** “麻烦抬一下头”“麻烦低一下头”模型理解正确，但当前词形校验拒绝；测试保留为失败。
4. **云端回退的触发依据仍有限。** 解析/参数校验能发现很多错，却不能识别所有格式正确的语义误解。云端也可能超时或返回不符合契约的结果。
5. **能力询问校验发现一处遗漏并已修复。** 修复前模拟用例“你能开灯吗”派发了开灯。已补上“能…吗”这一词形的澄清约束，并新增回归测试；没有在真实米家设备执行该命令。原始 240 条报告保留修复前数字，没有回填为通过。提示词和模型权重未据本轮答案修改。

## 性能、工程验证与完整性

本地文本推理平均约 0.364 秒，P95 约 0.462 秒；每次输入 269–279 token，平均约 273。合成语音后的模型推理平均约 0.388 秒。模型保持加载且存在前缀缓存，这不是冷启动或完整语音执行延迟。

最终代码在本机与机器人各通过 **87 项自动化测试**，包括本地优先、云端回退、无效云端建议拒绝、预算耗尽、底轮保护与此前的图执行测试。原两个项目 821 个代码/配置文件再次比较，新增、修改、删除均为 0。

同目录 `local/`、`hybrid/`、`hardware/` 保存逐条输入、期望、模型结果、路由、转写与执行记录；`local_stack_240.json` 为固定用例集。API 录音入口检查结果另见 `api_hybrid_voice_smoke.json`。测试代码、方法和结果报告也放在新项目中。
