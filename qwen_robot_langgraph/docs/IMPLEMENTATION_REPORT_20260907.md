## 实现范围

对话理解、请求校验、任务推进、暂停/继续/结束、错误分支均由 LangGraph 节点管理。场景 workflow 只声明经过审核的动作序列。硬件执行被拆到独立的 ROS、音频和设备适配器中。

已实现持久检查点、动作台账、稳定动作 ID、重复请求去重、资源互斥、过期任务拦截、语音队列及任务事件。收到暂停或结束请求后，图会等待执行器反馈；不会仅凭图停止运行就宣称设备已停止。硬件结果不明时保留资源，不盲目重复投食等操作。

完整会议导航流程保留了导航步骤，真实执行会被禁止底轮的策略拒绝。原地投影是显式的独立入口，不会把跳过导航说成完成了完整场景。

仍未迁移或未启用的内容包括旧版完整 Android App 协议、人脸库、提醒、天气、电影，以及实机运动视觉计数和宠物识别。后两者的工作流控制分支已做模拟测试，不能算作视觉能力的实机验收。

## 自动化测试

最终源代码：本机 **77/77** 通过，机器人 Python 3.10 环境 **77/77** 通过，机器人执行约 17.61 秒。本机约 5.21 秒。依赖固定为 LangGraph 1.0.10、SQLite checkpointer 3.1.1 等，完整版本见项目 requirements.lock。

测试覆盖：

- 底轮动作及串口底轮数据包拦截，包括零速数据包；非法参数、NaN、字符串布尔值、非法摄像头名称。
- 请求和动作去重、同一请求并发提交、节点重放时不重复投食。
- 资源冲突、独立任务并行、排队任务暂停、暂停后继续、未确认停止时不释放资源。
- 超时和迟到结果、异常结果保留、重启后不把历史状态当作已暂停或自动重发动作。
- 场景失败后的清理、只补偿已触发的动作、结束时清理、作废过期语音。
- 仅模拟的完整导航会议路径，以及导航失败时不启动投影。
- HTTP 接口、会话隔离、重复请求、非法/过大请求、跨站写请求拦截。
- 语音最终转写去重、过期转写和模型工具建议不直接触发硬件。
- 云端预算在多线程与重启后仍不超限；当前时间使用北京时间。

这些是工程行为测试，不是自然语言准确率统计。

## 仍然存在的问题

1. **头部回正仍慢。** 新项目当前采用受限头部测试配置，回正完整调用约 21–26 秒，底层仍出现 12 秒命令超时日志。最终角度、角速度及雷达恢复满足了场景验收条件，但这不是一个已经解决的控制性能问题，后续需要单独处理。没有修改旧项目的控制代码。
2. **自然语言模型仍会给出错误提议。** 本地 Qwen3-4B 的 18 条接口用例中，12 条直接满足期望；云端 6 条针对性用例中，3 条直接符合期望，其他出现否定句、指定角度或多动作格式问题。错误提议由参数和本轮指令校验拦截或要求澄清，不能把“拦截了错误”当成“模型答对了”。样本很小且偏向边界用例，不能据此推断通用准确率，更不能声称 95%。
3. **米家凭证过期。** 千问充值不会修复米家登录凭证；灯/投食机仍需要有效凭证才能完成实机控制验证。
4. **功能迁移尚未完整。** 当前重点是新架构和会议链路。旧版各项视觉业务、App 协议及长期记忆完整迁移仍未完成。
5. **进程重启后的物理恢复是保守状态。** 检查点和动作记录会保留，但无法确定设备结果时进入 unknown，不自动恢复运动或重复投食；完整的设备核实与恢复交互还没有做成产品流程。

## 云端测试预算

用户充值并提出上限后，实际生成 **7 轮**：1 轮语音、6 轮纯文本意图。预算台账还把 7 次连接各计一个名额，因此保守计数是 **14 / 100**，剩余 **86**。硬件场景、麦克风链路和大批量单元测试使用本地或模拟资源，没有新增云端生成。

新服务继续使用同一份持久预算，不会通过重启清零。后续用户手动操作控制台引发的云端请求也会累加。
